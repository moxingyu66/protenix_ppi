# C3 split protocol v0.1

Status: normalized v0.3 input prepared and validated; clustering and C3 algorithm `c3_hash_cluster_v0.2` frozen; Linux MMseqs2 execution pending

## Objective

Construct a primary test in which neither endpoint protein, nor any protein in its 30%-identity homology cluster, appears in training. Cross-pool pairs are quarantined rather than reassigned, because reassigning them would reintroduce node leakage.

## Why protein pools are not 80/10/10

If proteins are independently assigned 80/10/10 and only within-pool pairs are retained, approximately `0.8² / (0.8² + 0.1² + 0.1²) ≈ 97%` of retained pairs fall in training. The pair split is therefore badly imbalanced.

The working node-pool targets are 60/20/20. Under a simple random graph approximation, retained within-pool pair shares become approximately:

- train: `0.6² / (0.6² + 0.2² + 0.2²) ≈ 81.8%`;
- validation: approximately 9.1%;
- test: approximately 9.1%.

Actual PPI networks are not random, so realized ratios and retention must always be reported.

## Atomic assignment unit

The assignment unit is `homology_cluster_30`, not a single accession. Every protein must have a nonempty cluster ID generated by the frozen MMseqs2 protocol. A cluster is assigned atomically to exactly one protein pool.

## Frozen MMseqs2 command

Use full canonical sequences from the pinned UniProt release and MMseqs2 `easy-cluster` with actual alignment identity, bidirectional coverage relative to the longer sequence, and set-cover clustering:

```bash
bash protenix_ppi/scripts/run_mmseqs2_clustering.sh \
  protenix_ppi/data/processed/human_ppi_2026_03_v0.3/proteins.csv \
  protenix_ppi/data/processed/human_ppi_2026_03_v0.3/mmseqs30 \
  8
```

The script executes the following frozen scientific parameters:

```text
--min-seq-id 0.30
-c 0.50
--cov-mode 0
--alignment-mode 3
--cluster-mode 0
-s 7.5
```

`--cov-mode 0` requires at least 50% coverage relative to the longer sequence. `--alignment-mode 3` requests actual identical-residue fraction rather than the default score-derived approximation. The exact MMseqs2 version, input FASTA hash, raw cluster table hash, cluster counts, and final clustered-protein hash are mandatory evidence.

## Deterministic candidate generation

For candidate split seed `s`, each cluster receives a stable SHA-256-derived number from `s:cluster_id`. It is assigned to train, validation, or test according to the fixed 60/20/20 thresholds. Python's process-randomized `hash()` is never used.

Candidate seeds 0–999 are evaluated before any model output exists. The selected seed minimizes a predeclared score combining:

1. deviation of retained pair proportions from 80/10/10;
2. deviation of partition positive prevalence from global retained prevalence;
3. deviation of protein-pool proportions from 60/20/20;
4. a small reward for retaining more labeled pairs.

Each partition must contain the declared minimum number of positive and negative examples. Ties are resolved by the smaller seed.

## Pair handling

- Eligible labeled pairs whose endpoint clusters are assigned to the same pool are retained.
- Pairs whose endpoints are assigned to different pools are written to `cross_partition_pairs.csv` with reason `cross_partition_quarantine`.
- A nonempty `complex_group_id` is also atomic: if the union of endpoint pools
  across any pair in that evidence group contains more than one pool, every
  pair in the group is written to quarantine with reason
  `complex_group_cross_partition_quarantine`. A group is never split between
  training, validation, and test even when some of its individual edges would
  otherwise be within-pool.
- Quarantined pairs are not negative examples and are not used for training or evaluation.
- Validation and test pairs are marked `C3` relative to the training pool.
- Non-eligible, excluded, quarantined, or unlabeled source pairs are outside this generator's primary output.

## Required outputs

- `splits.csv` — retained assignments;
- `cross_partition_pairs.csv` — explicitly quarantined cross-pool pairs;
- `protein_pool_assignments.csv` — every protein, its atomic homology cluster, and assigned pool;
- `c3_split_metadata.json` — algorithm version, input hashes, selected seed, objective score, realized counts, prevalence, and retention.

All outputs must pass `validate_dataset.py` together with the source normalized tables.

For the primary dataset, use the guarded finalizer after the Linux clustering
script completes:

```bash
python3 -m protenix_ppi.scripts.finalize_c3_benchmark \
  --dataset-dir protenix_ppi/data/processed/human_ppi_2026_03_v0.3
```

It revalidates the MMseqs2 version, parameters and hashes, creates the split in
a staging directory, runs the complete dataset validator, builds all fixed
evaluation cohorts with seed `20260915`, and writes
`benchmark_freeze_manifest.json` last. Existing final outputs cause a hard
failure so that a benchmark cannot be silently regenerated after scoring.

After validation, run `build_evaluation_cohorts.py` exactly once with seed `20260915`. Freeze its membership and metadata hashes before any B0 or B1 score is generated. This additional step is required because the evidence pool is strongly positive-enriched; it does not alter C3 assignments or create synthetic negatives.

## Limitations to report

- C3 evaluates novel protein identities/families, but it does not prove absence of all pretraining exposure.
- High-degree PPI networks can cause substantial pair loss after node separation.
- Selecting a balanced seed uses labels for experimental design; it must happen before model scoring and follow this frozen objective.
- If a partition lacks sufficient positives or negatives, expand the dataset or revise the predeclared minimum. Do not manually move individual proteins after inspecting model results.
